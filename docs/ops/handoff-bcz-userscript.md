## 【给 DeepSeek 的任务】

你在改一个开源小项目：**训练家图鉴**（`https://github.com/lilia-shound/pokemon-dex`，
站点 `https://lilia-shound.github.io/pokemon-dex/`）——
「读满一定时长 → 随机收服一只宝可梦」的进度记录器。
你负责其中一个**数据源的客户端脚本**：

**`plugin/bcz-dex.user.js`** —— 装在**百词斩**（背单词 App 网页版）上的油猴脚本。
它在页面上找「标签 + 数字」，认出来就算「今天背了多少个词」，然后把结果报给服务端。

### 背景（你需要知道的）

- **口径**：口径是**「新学 + 复习」**。页面上两个标签都有 ⇒ 相加；只有一个 ⇒ 当成**半个口径**，
  浮层上要跟用户说清楚。`per = 100` 个词 = 1 个额度（这个 `per` 在服务端，**你别改**）。
- **现在的状态**：脚本里有一张「关键词清单」（分「总数类」和「分量类」两组），
  靠 `标签 + 数字` 的正则去匹配。**但这些关键词是猜的** ——
  百词斩的学习界面在登录后面，沙箱里拿不到它的真实 DOM / 文案 ⇒ **真机上一次都没验过**。
- **认数逻辑的纯函数部分**已经能在 node 里跑测（见下），浏览器里也有观感断言。

### 这次要做的事（就这三件，别多做）

1. **关键词表要好维护**：集中成一张表、长的排前面、**加中文注释说明每组是干什么的**，
   加一个「备用关键词」区（注释写清怎么往里加），别把正则散落在代码各处。
2. **认不出的时候要能自诊断**（这是本次最重要的产出）：
   标签没匹配上时，**在控制台打印**它看到的东西 —— 页面上的相关文字片段、
   附近出现的数字、以及为什么没认出来（哪个标签没命中 / 命中了但数字不合理）。
   目标是：用户（或维护者）在真机上打开控制台就能看懂「它为什么没认出来」，
   而**不需要**改代码重装。
   ★ 顺便在浮层上给一句人话提示（类似「没认出来？点这里看诊断」），别只丢到控制台。
3. **兜底要克制**：标签匹配不上时，**可以**退一步在页面里找「像数量」的数字，
   但**必须排除常见噪声**（时间、进度条百分比、等级/序号、连续天数、排名…）。
   ★ **宁可认不出，也不要认错** —— 认错会把假数字报给服务端，
   用户的图鉴就会多出不存在的进度。**拿不准就不认**，让用户截图反馈。


- ✅ 整套**全绿**、且**一个测试都不能被跳过**。
  ★ CI 里有一道「不许有测试被静默跳过」的检查（`scripts/check_no_skipped.py`）：
  依赖没装好时 unittest 会 *skip* 而不是 *error* ⇒ **少测几十条也是绿的**。
  所以：**别新写「装不上就 skip」的分支**；现有的 `tests/test_bcz_userscript.py` 里
  「找不到 node / 没有 playwright 就 raise SkipTest」的写法，在 CI 里两者都有 ⇒ 不 skip。

- ✅ 浏览器层的断言（Playwright）在 CI 里是装好的（`pip install playwright` +
  `python -m playwright install --with-deps chromium`），本地如果没装 chromium，
  照 `tests/browser_path.py` 的 `chromium_path()` 找，**别写死版本号路径**。
