**每轮跑在一个全新的会话里**（上一轮的对话不会带进来 —— 这是故意的：常驻会话会把上下文越堆越大，一天几轮就够把额度烧光，2026-11-26 就因为这个连续失败 5 次被平台自动暂停过）。
★ **口径全在这份提示词里 + 仓库里**：`docs/ops/cron-notes.md` 是运维口径、`data/dex.json` 是账本状态、`git log` 是上一轮干了什么 —— 要「上一轮发生了什么」就去读仓库，**别去翻对话历史**。

**第 0 步（重要）**：每次运行可能是全新的空沙箱，目录不一定还在。先检查：
  `ls /workspace/pokemon-reading-dex/scripts/award.py 2>/dev/null`
不存在就克隆（仓库是 public，免认证）：
  `git clone --depth 1 https://github.com/lilia-shound/pokemon-dex.git /workspace/pokemon-reading-dex`
克隆要点（踩过的坑）：
- 默认 30 秒超时会把 clone 打断。跑 clone 时给足时间（bash timeout 300 秒以上），并加 `--depth 1`。
- 被打断会留下半成品目录（有 .git/site/tests，没有 scripts/）。`rm -rf` 偶尔报 "Directory not empty"，重试 1-3 次就删得掉，别换路径。
- 判据是 `scripts/award.py` 在不在，不是目录在不在。
- **沙箱到 GitHub 的 TLS 握手不稳定**，clone/push 可能报 `GnuTLS recv error (-110)` / `gnutls_handshake() failed` —— 这是网络抖动不是代码问题，重试 1-3 次（间隔 5 秒）通常就成了。别因此改代码。
克隆后 `cd /workspace/pokemon-reading-dex && git log --oneline -1` 确认有代码。

**判定步骤**：
1. `cd /workspace/pokemon-reading-dex && python3 scripts/collect_worker.py` —— **先收免登录投递通道**（S8 上线于 2026-11-25）
   - 这是**新通道**：网页版番茄钟、KOReader 落地页、备考记数页现在把数据**直接 POST** 给一个免登录的公网接收端（不用登录 GitHub、不用开 issue）；cron 从那个接收端把队列拉下来、校验、并进账本。
   - 需要环境里的 `WORKER_URL` 与 `WORKER_ADMIN_TOKEN`（admin token 只在 secret 里，**不要打印**）。
   - 输出「[投递] 未配置 WORKER_URL / WORKER_ADMIN_TOKEN，跳过」= 没配 ⇒ 如实说一句「投递通道没开」，**不要假装收过**；
   - 输出「[投递] 采纳 …」= 有新报告被采纳；「[投递] 队列是空的」= 没有（正常）；
   - 输出「[投递] 拒收 …」= 服务端拒收了一条（如实提一句，**不要自己动手修**）；
   - 输出「[投递] 拉取失败 …」= **这一步是旁路**，跳过即可，**绝不能**因此不发奖。
     ★ 拉取自带重试（3 次 × 60 秒）；**拉取失败 ≠ 数据丢了** —— 条目还在队列里，下一轮会补上（并账取 max ⇒ 幂等）。
   - ★ **不要用 `&&` 把它和后面的步骤串起来** —— 它失败时会把后面的发奖一起带崩。
1.5 `cd /workspace/pokemon-reading-dex && python3 scripts/collect_reports.py` —— **再收老办法的投递箱**（GitHub Issue）
   - **老办法还在**（已经装好的旧页面照常用）⇒ **两条通道都要跑**，别只跑一条。
   - 输出「[采纳] #编号 …」= 有新报告被采纳；「没有可采纳的报告」= 没有（正常）。
   - 输出「[跳过] #编号 …」= 有人提交了非法报告，**不要自己动手修**，如实提一句就行。
   - 脚本需要环境里的 `GITHUB_TOKEN`（和 deploy.sh 用的是同一个）。

3. `cd /workspace/pokemon-reading-dex && python3 scripts/award.py` —— 判定并抽卡
   - 输出含「★ 获得」= 达标了，抽到了新宝可梦

   - 输出含「未达标，今天没有宝可梦。」= 今天还没凑够额度
   - 输出含「[失败] 取数失败」= **取数坏了**（Key 失效 / 微信读书 skill 版本过期 / 网关抖动），不是她没读书 —— 如实报「取数失败」+ 原因，**不要报成「今天没读够」**，也不要发奖
3.5 `cd /workspace/pokemon-reading-dex && python3 scripts/notify.py` —— 发邮件通知（S7 上线于 2026-11-23）
   - 输出含「[通知] 已发送」= 发出去了一封（收服了新宝可梦 / 连读快断了）
   - 输出含「[通知] 未配置」= 姜来还没配 Resend 的 key ⇒ **如实说一句「邮件通知没开」**，
     不要假装发了

4. `cd /workspace/pokemon-reading-dex && bash scripts/deploy.sh` —— **满足下面任一条就要跑**：
   - 第 3 步真的抽到新宝可梦（输出含「★ 获得」）；**或者**
   - 第 1 步（投递通道）采纳了报告（输出含「[投递] 采纳」或「账本已更新」）—— **这个不能漏**：
     账本里的量如果没推上去，这轮番茄钟/KOReader/背单词就白干了（下次不会重来）；**或者**
   - 第 1.5 步采纳了报告（输出含「[采纳]」或「账本已更新」）——
     **这个也不能漏**：账本里的量如果没推上去，这轮番茄钟/KOReader/背单词就白干了（issue 已被关闭，数据找不回来）；**或者**
   - **今天的读数变了**（跑完第 2/3 步后 `git status --short` 显示 `data/dex.json` 或 `site/dex.json` 有改动）——
     **这条也不能漏**：图鉴页顶部的「今日额度」面板如果一直不部署，会显示过期的进度。
     一天会部署好几次，这是正常的，别怕提交多。
   - **历史数据变了**（跑完 3.6 后 `git status --short` 显示 `data/history.json` 有改动）——
     图鉴页的「最近 30 天」热力图和堆叠柱读的是 `site/history.json`，不部署就看不到新的。
   deploy.sh 内部用 GIT_ASKPASS 传 token，**不要自己把 token 拼进 URL**（会明文打印）。
   ⚠️ 远端 main 可能已经有新 commit（别的任务也在推），deploy.sh 自己的 push 失败时重试即可；
   **不要为此 reset 掉远端的提交**。
5. 汇报规则：
   - 抽到了：用一两句话告诉用户今天收服了哪只（闪光要明确说出来）、连读几天、图鉴多少/1028
   - 没抽到：只用一句话带过（比如「今天还差 1 个额度：微信读书 29 分钟（1 个）+ 番茄钟 0 分钟 + 背单词 0 个 + KOReader 0 分钟」），不要展开
   - **邮件发出去了**（notify.py 说已发送）：在汇报里提一句「邮件也发了」
   - **邮件没开**（notify.py 说未配置）：如实说一句「邮件通知还没配 key，没发出去」
   - clone 失败或取数失败：如实说失败原因，**绝不伪造结果、绝不发奖**
   - **判定「有没有抽到」只看 `data/dex.json` 的 `collected` 真多一条**。award.py 只更新 `today` 滚动块（date/seconds）时，git status 会显示 M data/dex.json，那是正常状态、不算抽到。

**★ 当前口径（2026-11-23，S7 日常闭环上线后）**：
- **达标线 = 2 个额度**（`perAward = 2`）。微信读书 900 秒 = 1 个额度，番茄钟 25 分钟 = 1 个额度，KOReader 15 分钟 = 1 个额度，背单词 100 个 = 1 个额度，四边加起来凑满 2 个额度掉 1 只。
- **微信读书 / 番茄钟 / KOReader / 备考是四个独立的源**（有意设计）：各自按天取整后**额度相加**。
  别把它们并成一个源 —— 账本对「同源同一天」取 max，合源会把其中一个平台的量吃掉。
- **不要自己改 `data/sources.json` 的 `perAward`**（现在是 2）。想回「读满就掉」的老节奏就改成 1，代码不用动。
- **也不要自己改各源的 `per`**（那是「1 额度要多少原始单位」）。目前是：weread 900 秒、pom 25 分钟、koreader 15 分钟、words 100 个。
  改 `per` 只会让**下一次部署后**站点上的显示跟上（站点读的是部署同步过去的那份注册表），
  但**账本与发奖用的是 `data/sources.json`** ⇒ 真要改的话，要等下一次 deploy 跑过才完全一致。
  没得到她明确同意，**不要改任何 `per`**。
- `data/dex.json` 已经是 v2，**不要再跑 `--migrate-only`**（它只该在迁移当天跑一次，跑多了会把当天的读数清零）。
- `award.py` 会**一次结清所有待发奖日**（升序，最多 3 天），所以**一轮可能输出多个「★ 获得」** —— 遇到多个就都报出来，并说明哪只是补发的（输出里会写「★ 补发 YYYY-MM-DD 获得 …」）。
- 进化链的「保底闪光」：**这条链首次被收服后养满 30 天，再次抽到它就必定闪光**。所以某天可能输出「[保底] … 这次必闪」—— 汇报时要提一句这是养出来的保底。
- ✅ **图鉴页顶部现在是「今日额度」面板**（S5 上线了）：每个启用的源一行（原始量 → 折算几个额度），下面是合计 `x / 2 个额度`。
  **四个源的量都能看见** ⇒ 她要是「读 20 分钟 + 一轮番茄钟」或「读 20 分钟 + KOReader 15 分钟」或「读 20 分钟 + 背单词 100 个」已经够了，别报成「还没达标」。
- ✅ **进化链的形态改写（S6 上线了）**：抽到某条链里**阶更高**的成员时，同链里阶更低的已收服条目，
  `collected[].form` 会推进成高阶那只 ⇒ 图鉴页那一格显示的是**进化后的形态**（副标题写「宝贝龙 → 暴飞龙」）。
  链级养成那块也会显示「当前形态 暴飞龙（第 2 阶）」。
  ★ 形态推进**不需要你做任何事** —— award.py 自己会算（幂等），**不要手动改 data/dex.json 的 form 字段**。
  ★ 汇报时如果抽到的宝可梦**进化了同链已收服的低阶成员**，可以顺带提一句「宝贝龙进化成暴飞龙了」这种（她会觉得有趣）；
    不必提就不提，不算报错。
- ✅ **邮件通知（S7 上线了）**：`scripts/notify.py` 是**旁路** —— 它只读 `data/dex.json`、
  只写 `data/notify_state.json`，**结算核心一行没改**。
  ★ 判定「有没有新的宝可梦」看的是「**有没有通知过**」，不是「是不是今天」——
  因为 award.py 会一次结清所有待发奖日，补发的那只也要通知（邮件里会标出收服日期）。
  ★ 提醒邮件的判定：连读 ≥ 2 天、当天没达标、北京时间 ≥ 21:00、当天没发过 ⇒ 一天最多一封。
