# 背单词记数 · 一步步的手册（怎么记、怎么交、交上去发生了什么）

这份文档是给你看的：手机上一个网页，记下今天背了多少个词，把它交回图鉴，
最后**自己验一遍数字对不对**。

项目总览在 [仓库根 README](../README.md)。

---

## 这套东西是两段接力

```
你（手机浏览器）
  └─ 在记数页上填「今天背了多少个词」→ 存在**本机浏览器**里
       └─ 点「去 GitHub 提交」→ 打开**预填好的**新建 issue 页
            └─ 你点一下 Submit → 服务端的定时任务读这条 issue
                 └─ 并进逐日账本 → 当天额度够了就掉一只宝可梦
```

两段的分工要记牢：

- **记数页只报数**，它不发任何写请求（纯静态页收不了 POST），也不抽卡。
- **只有服务端能记账和掉宝可梦**。

---

## 你要准备什么

- 一部能上网的手机（记数 + 提交 issue 用）。
- 一个 **GitHub 账号**，而且它得是 `lilia-shound/pokemon-dex` 这个仓库的**管理员或协作者**
  —— 服务端只认这些身份的 issue（`author_association` 在 `OWNER` / `MEMBER` / `COLLABORATOR` 里）。
  别人（或匿名）提的 issue 会被跳过，而且**不会被关掉**，留给人工看。
- 仓库的 issue 功能是开着的（默认就开着）。

## 第一步：打开记数页

<https://lilia-shound.github.io/pokemon-dex/words/>

手机浏览器打开就行。**建议加到主屏幕**（Safari / Chrome 都有「添加到主屏幕」，
这样下次一点就开，像个 App）。

页面长这样：

1. 上面一个大数字输入框 —— 「今天背了多少个词」。
2. 下面四个快捷按钮：`+10` / `+20` / `+50` / `清零`。
3. 再下面是「最近 7 天」：一天一个小卡片，**点某一天可以补录**（今天那一格是高亮的）。
4. 最下面是「去 GitHub 提交」按钮。

> ⚠️ **这个页面的地址要等发布之后才有** —— 还没发布的话点过去是 404。
> 仓库里那一份在 `site/words/`（自己起个静态服务器也能看）。

---

## 第二步：记数

在输入框里填今天背的词数（或者用快捷按钮加）。填完立刻能看到折算结果：

| 你填的 | 页面显示 | 说明 |
|---|---|---|
| 0（没填） | 「今天还没记」 | 不显示一个孤零零的 0 |
| 99 | 「99 个 → 折算 0 个额度」 | 零头不计 |
| 100 | 「100 个 → 折算 1 个额度」 | 够一个额度 |
| 250 | 「250 个 → 折算 2 个额度」 | 够掉一只宝可梦 |

**额度按天算，零头不跨天凑**：今天 150 个 + 明天 50 个 = 1 + 0 = **1 个额度**（不是 2）。

数字存在**本机浏览器**里（localStorage），不上传、也不联网 ——
只有你点提交的时候才会往外发东西。

- **补录前几天**：点「最近 7 天」里某一天，那一格变成选中状态，输入框里填的数就是那天的。
- **刷新不丢**：数字记在本机，刷新、关掉再打开都还在。
- **隐私模式**：浏览器的隐私模式不让存东西 ⇒ 页面还能用，但**刷新就没了**（页面会提示你）。
- **记得住 30 天，看得见 7 天**：本机存的是最近 30 天（服务端一次最多收 30 天），
  但页面上只画最近 7 天。超过 7 天的那些天**不会被丢掉**，提交时会一起交上去 ——
  页面上会有一行提示告诉你「这份报告里有几天不在最近 7 天里」，免得你交出意料之外的量。
- **带 `?words=150` 的链接**：只在**当天还没记**的时候预填（页面上会说「已按链接预填 150 个，可以改」）。
  那天已经记过数的话，链接**不会覆盖**你记的数 —— 页面会告诉你它没有覆盖。

## 第三步：交上去

点「去 GitHub 提交」。

会打开 GitHub 的**新建 issue** 页，标题和内容都已经填好了：

- 标题：`[report] words 2026-11-22`（`2026-11-22` 是你记的**最新的一天**）
- 内容：`{"v":1,"source":"words","days":{"2026-11-22":150,"2026-11-21":80}}`

**在那个页面上点一下 `Submit new issue` 才算交上去** —— 光打开不算。

> 只有**有数的天**会进内容里（零不报）。
> 单日超过 500 个词的话，页面会替你夹到 500 并明确告诉你夹了多少 ——
> 服务端对超上限的报告是**整份丢掉**的，不夹的话你会以为交上去了。
> 「最近 7 天」之外的日子（最多到 30 天前）也会一起进去，页面上有一行提示写着是哪几天。
>
> 如果备考源哪天被**停用**（注册表里 `enabled` 不是 true），服务端会拒收这一类上报 ⇒
> 页面会直接把提交按钮按掉并说明原因，不让你白交。

---

## 第四步：交上去之后发生了什么

1. 服务端的定时任务（`scripts/collect_reports.py`）拉这个仓库的 open issue，
   只看标题以 `[report]` 开头的那些。
2. 校验：作者身份得在白名单里、`v` 得是 1、`source` 得是 `words`、
   日期得是合法的 `YYYY-MM-DD` 且不晚于今天、每天的数不能超过单日上限 500。
   **任何一条不过就丢弃整个 issue**（不部分采纳）。
3. 并进逐日账本：**同一源同一天取 max** ⇒ 重复交不吃亏，放心重交。
4. 回一条评论算给你看（哪天多少个词、共折算几个额度），然后关掉这个 issue。
5. 当天**所有源**的额度加起来够了（`perAward` = 2），且当天还没发过奖 ⇒
   从还没收服的池子里掉 1 只宝可梦进你的图鉴。

额度**跨天清零**：今天攒的额度今天没用完，明天就没了（一天最多 1 只）。

## 自己验一遍（对账）

1. 记数页上填一个数 ⇒ 「去 GitHub 提交」⇒ 在 GitHub 那个页面上点 Submit。
2. 打开仓库的 issue 列表 ⇒ 找那条 `[report] words …` ⇒ 等服务端跑完（最多几分钟），
   它会回一条评论，写明「已采纳：N 天的量（words），该源口径共折算 M 个额度」。
3. 打开图鉴页 <https://lilia-shound.github.io/pokemon-dex/> ⇒ 看「已收服」是不是多了一只。

数字对不上时按这个顺序查：

| 现象 | 多半是 |
|---|---|
| issue 提交了但没被采纳 | 看服务端日志有没有写「丢弃」—— 多半是超上限或日期在未来 |
| issue 被采纳了但没掉宝可梦 | 当天**总额度**（所有源加起来）没到 2，或者当天已经发过奖了 |
| 页面显示的额度和服务端不一样 | 记数页读的是站根那份注册表（`site/sources.json`，部署时由 `data/sources.json` 自动同步）⇒ 两边**本来就应该**是同一份。不一样的话，多半是仓库里的 `site/sources.json` 被人手改过 ⇒ 跑一下测试 `python3 -B -m tests.test_words_landing` |

## 如果你用百词斩：可以少打几个字

有个**油猴脚本**能替你从百词斩网页版上认出「今天背了多少词」，
给一个小浮层，点「打开记数页」就把数字带过去（**最后那一下还是你点** ✓）。

装法：油猴（Tampermonkey）里新建脚本，把这个地址的内容整份贴进去保存 →

<https://lilia-shound.github.io/pokemon-dex/bcz-dex.user.js>

**装之前先知道这几条**（免得你对着一个不工作的脚本干瞪眼）：

- **它只能在网页版上跑。** 你在手机 App 里背的词，它读不到。
  不过百词斩的网页版和 App **数据是通的** ✓ —— 手机背完，打开网页版它就能看到今天的量。
- **它认的是中文标签**（「今日学习 137 词」「新学 30 复习 107」这类）。
  百词斩哪天改版，我就得跟着调 —— **要是它没认出来，把那个页面的截图发我，
  我按真实文案改两行就行** ✓（不用你折腾）
- **它不会把「剩余」当成「已完成」**：界面上那个「需新学 15 / 需复习 1」是**还没背的**，
  脚本认不出来、也不会拿它当今天的成果 ✓
- **它只带数，不代提交** ✓ —— 浮层上会写明这个数是从哪儿来的
  （页面文字 / 接口 / 你手填）✓，你一眼就知道可不可信 ✓
- 它的按钮打开的是**记数页**（带 `?words=数量`），你确认一下数字，再点「去 GitHub 提交」✓
