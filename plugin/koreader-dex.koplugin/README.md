# 训练家图鉴 · KOReader 插件

在 KOReader 里读的书，读了多少分钟，弹个二维码让手机扫一下 —— 分钟数就报回
「训练家图鉴」中枢，凑够了额度掉一只宝可梦。

插件只干一件事：**把你读了多少分钟报上去**。抽卡在服务端，插件不抽卡、不碰你的图鉴、
也没有你的 GitHub 密码。书名、笔记、划线一概不上报（只报总分钟数）。

完整的手把手操作 + 对账步骤在 [`docs/koreader-setup.md`](../../docs/koreader-setup.md)。

---

## 装在哪

把整个 `koreader-dex.koplugin/` 目录复制到设备的 **`plugins/` 目录**，然后**重启 KOReader**：

```
plugins/
  koreader-dex.koplugin/
    _meta.lua              -- 插件的名字和简介
    main.lua               -- 主体：读库、弹窗、弹二维码
    koreader_dex_report.lua -- 纯计算部分（拼链接、算额度、算日历窗口）
    README.md              -- 这份
```

Kindle 上一般是把挂载出来的 `koreader/plugins/` 目录（常见是 `/mnt/us/koreader/plugins/`）
拷进去；**固件路径不一样的话，以「设备上的 koreader/plugins/ 目录」为准**，别照抄别人的路径。

复制完要**退出 KOReader 再打开**（关掉书不算重启）。重启后主菜单里会多一项「训练家图鉴」。

> 想知道这插件到底能干什么、不能干什么 → 看下面的「它不干什么」。

---

## 菜单里有什么

主菜单（☰）里找到「**训练家图鉴**」，点开是三个选项，**文案一字不差**：

| 菜单项 | 干什么 |
|---|---|
| `汇报阅读时长（最近 7 天）` | 读最近 7 个自然日的时长 → 弹二维码（带 7 天的链接） |
| `只汇报今天` | 只报今天 → 弹二维码（带 1 天的链接） |
| `自检` | 打一张最近 30 天的表（日期 / 分钟 / 页数）—— **对账用** |

找不到这一项 = 插件没被认出来：目录层级错了（多套了一层文件夹）、少了 `_meta.lua`、
或者忘了重启 KOReader。

### 汇报时屏幕上是什么

先弹一段字，看完关掉它，才会弹二维码（二维码窗口的标题是 `训练家图鉴 · 汇报阅读`）。

「只汇报今天」：

```
今天 25 分钟 → 折算 1 个额度
同一条链接已经复制到剪贴板了（二维码扫不出来时可以手动粘贴）
刚读完的那几页可能还没落库（内置 statistics 是攒着写库的：每 50 次翻页 / 关掉书 / 息屏才落库）—— 关掉书或息屏后再汇报
```

「汇报阅读时长（最近 7 天）」：

```
最近 7 天（3 天有记录）共 95 分钟 → 折算 5 个额度
同一条链接已经复制到剪贴板了（二维码扫不出来时可以手动粘贴）
刚读完的那几页可能还没落库（内置 statistics 是攒着写库的：每 50 次翻页 / 关掉书 / 息屏才落库）—— 关掉书或息屏后再汇报
```

几点要留意：

- **「折算 N 个额度」是 KOReader 这一个源的额度**，15 分钟 = 1 个额度，按天算、零头不计。
  微信读书和番茄钟的额度是另外算的，最后会**相加**。所以「折算 1 个额度」不代表今天一定掉宝可梦
  —— 得全源加起来满 2 个额度才掉 1 只。
- **二维码里是落地页短链**（`https://lilia-shound.github.io/pokemon-dex/koreader/?days=...`），
  不是 GitHub 的长链接 —— Kindle 上没法登录 GitHub，扫了长链也交不上去。手机扫开后有一个
  「去 GitHub 提交」的按钮，那一步才交数。
- **0 分钟的天不会报**（不足 1 分钟的会被取整成 0，报上去也没用）。所以链接里只会有真有阅读的日子。
- 剪贴板那行**不一定出现**：复制失败（设备没有剪贴板、或那个 API 在你的 KOReader 版本上不存在）
  时插件会安静地跳过这一行 —— 插件不会因为一个兜底功能崩掉。

### 自检表长什么样

```
训练家图鉴 · 自检

数据来源：/mnt/us/koreader/statistics.sqlite3
  （KOReader 内置 statistics 插件自己记的库）
口径：与内置 statistics 完全同一条 SQL ——
  按设备本地时区分天；同一页当天读多次会累加；
  页数按内置的 page_stat 视图重算（reflowable 重排过也算）。
下面每行是：日期  分钟  页数（只列有记录的天）。
  分钟 = 丢掉秒数（内置那边显示 时:分:秒，这边是整分钟、向下取整）。

最近 30 天（3 天有记录）：
2026-11-21    45 分钟     12 页
2026-11-20     0 分钟      1 页
2026-11-19    25 分钟      3 页

合计 70 分钟 → 折算 4 个额度

怎么对照：KOReader 里打开「工具 → Reading statistics →
Time range」，页面标题是「Time range statistics」，
里面有一项「Last week」（最近 7 天，逐天），
30 天那张叫「Last month by day」。
它每行是「日期 (星期几)  时长 (N 页)」，例如
「2026-11-19  00:00:45 (1 page)」。
对照：「Last week」是最近 7 天、「Last month by day」是最近 30 天，
它们也只列有记录的天 ⇒ 跟上面这张表里同一个日子的那行比：
分钟数要一样、页数要一样。口径一样 ⇒ 必须一模一样。

刚读完的那几页可能还没落库（内置 statistics 是攒着写库的：每 50 次翻页 / 关掉书 / 息屏才落库）—— 关掉书或息屏后再汇报
```

表是**等宽字体**排的（两列才对得齐），而且**可以滚动**（表长的时候往下翻）。

看这张表的时候注意两点：

- **不足 1 分钟的天也在表里，分钟数显示 0** —— 内置 statistics 那边的
  「00:00:45 (1 page)」在我们这儿就是 `0 分钟 1 页`。这不是 bug，是为了让你能逐天对上号。
- **分钟数是整分钟、向下取整**；内置那边显示的是 时:分:秒。对照时要把秒数去掉再看。

## 弹出来的那些提示分别是什么意思

插件不弹英文报错，只弹下面这几句人话。看到哪句就照哪句做：

| 你会看到的原文 | 什么意思 | 你该做什么 |
|---|---|---|
| `KOReader 的统计数据库还没建 —— 先读一会儿书，或打开一次 Reading statistics` | 设备上还没有 `statistics.sqlite3` 这个库 | 读一会儿书，或者打开一次 KOReader 的「Reading statistics」 |
| `先在 KOReader 里打开一次 Reading statistics，让它把数据库升级` | 库在，但没有 `page_stat` 视图（老库没升级过） | 打开一次「Reading statistics」，让它自己升级 |
| `内置的 Reading statistics 没打开 —— 先在 KOReader 的「设置 → Reading statistics」里打开它，不然读到的都是旧数据` | 内置统计被关掉了 | 把内置统计打开（在「Reading statistics」那一项里，勾选状态叫 `Enabled`；提示语里写的「设置 → Reading statistics」指的是同一件事） |
| `还没有阅读记录` | 库能读，但这个窗口里没有分钟数 | 读满 1 分钟再试（不足 1 分钟会被取整成 0，所以看起来像「没有」） |
| `读不了 KOReader 的统计数据库 —— 先在 KOReader 里打开一次 Reading statistics，让它把数据库升级`（后面可能跟着括号里的原始错误） | 其它 SQL 错误 | 先按上面那句去开一次「Reading statistics」；还不行就把括号里的原文记下来 |

还有一句**每次都会出现**在最后：

> `刚读完的那几页可能还没落库（内置 statistics 是攒着写库的：每 50 次翻页 / 关掉书 / 息屏才落库）—— 关掉书或息屏后再汇报`

这不是出错，是**内置 statistics 的写入是攒着的**：翻满 50 页、关掉书、或者息屏，才写一次库。
所以刚读完的几页这时候还没进库 —— **关掉书或者息屏之后再汇报**，数字才全。

## 它不干什么

- **不发任何网络请求。** 插件只读本地数据库、弹个二维码。二维码里是一串字符，扫不扫、点不点
  都是你的事。插件不知道你的 GitHub 账号，也没有 token。
- **不抽卡。** 掉不掉宝可梦由服务端决定，插件这边什么都不写。
- **不上报书名、笔记、划线。** 只报分钟数。
- **不能在没有网络的 Kindle 上直接提交。** 二维码是死的链接，扫码那一步需要手机能上网。

## 沙箱里没能验的部分

写这份说明的时候**没有真机**（没有 Kindle、没有 Android），下面这些只能靠你上手时确认：

1. 菜单里到底出不出现、出现在哪一组（不同 KOReader 版本 / 语言的分组文案会不一样，
   实在找不到就翻到主菜单底部）。
2. e-ink 屏上那个二维码**够不够大、相机扫不扫得出来**。扫不出来就用剪贴板那条路
   （见 `docs/koreader-setup.md`）。
3. **剪贴板复制**能不能成 —— `Device.input.setClipboardText` 这个 API 我们没能从上游源码里
   逐条核实到，插件用 `pcall` 包住了，失败就当没这回事（那一行提示不会出现）。
4. 真机上 `conn:exec` 返回值的形状，是不是和代码里假设的一样。
5. **Android 版**（同一台手机既是阅读器又要扫码）：那条路走不通，插件会**把链接复制到剪贴板**，
   你把剪贴板里的链接粘到浏览器打开即可。

如果哪一步的数字对不上，别急着提交 —— 按 `docs/koreader-setup.md` 的「四步对账」走一遍，
能定位到是哪一环错了。
